# 模式显示修复与实板诊断（2026-11-05）

## 已修改
- 调速模式使用实板绿色DIG1/0x68，1..4档单灯顺序改为LED8、LED7、LED6、LED5（G/F/E/D）。
- 情景模式使用红色DIG2/0x6A，保持原LED5、LED6、LED7顺序。
- 保留两个调试观察量：`tool_mode_key_raw`记录最近成功读取的原始键码；`tool_mode_key_read_ok`记录最近一次读事务是否成功。读失败保留旧raw并置read_ok=0。它们不参与控制，不写Flash。
- 更新既有灯显示/关灯测试期望，以及与当前源程序39/58/78/98%表不一致的旧占空比测试期望。未改档位表、保护配置、PWM、方向或启动联锁。

## 占空比调查
用户确认满扣扳机，在电机相线测得约42/62/62%。当前软件调速1..4档命令上限为39/58/78/98%，PWM_PRIOD_LOAD=1874，计数分别730/1086/1461/1836。二、三档目标不同，没有发现62%软件限幅。

相线波形包含六步换相的导通、关断和悬空区间；对整段相线自动测量的占空比不能直接当作16kHz PWM目标。需对稳定运行时单个PWM导通窗口测量，并对照`tool_mode_list.mode/speed_gear`、`motor_control_list.pwm_duty_aim`、`motor_control_list.pwm_duty_virtual`、`mc_core_list.pwm_actual_runing_data`和`TIM1->CCR1/ARR`。若二、三档CCR分别接近1086/1461而相线仍报62%，优先核对相线测量窗口；若CCR也相同，再根据模式、目标和板上固件版本定位。

## K3尚待实板定位
原理图K3通过R15接DIG3与A/KI1，键码0x46；K2对应0x47。当前软件连续三次成功的10ms K3采样即可进入情景模式，未发现软件入口屏蔽。真实TM1650总线驱动、去抖、模式与LED代码集成测试也验证了这条路径，但不能证明实板按键能产生这个键码。

下一步：按住K3查看`tool_mode_key_read_ok`和`tool_mode_key_raw`。
- read_ok=1且raw=0x46：再查看`tool_mode_list.mode`（情景=1）、`scene_gear`及灯是否切红。
- read_ok=1但raw不是0x46：记录实际值，核对实际板键位/接线与原理图。
- read_ok=1但按下raw不变：核对K3、R15、DIG3及A/KI1支路。
- read_ok=0：最近读事务失败，raw为旧值，需核对总线时序与连接。

未扩大未知键的接受范围，不能声称实板K3故障已经修复。
