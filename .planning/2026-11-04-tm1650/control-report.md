### 控制接口

- `tool_mode_list` 含 `mode`、`speed_gear`、`scene_gear`、`save_pending`；默认调速1档，情景初始1档。两种模式各自记忆挡位。
- K2仅严格接受0x47，K3仅严格接受0x46。切到另一个模式仅切换，重复按当前模式键分别循环1..4和1..3。
- `tool_mode_key_handle()` 每1ms调用、每10次进行一次TM1650_ReadKey；返回1表示本次进行了读总线事务，包括失败。按下/释放均需要3次连续稳定有效样本；按住只触发一次；未知/组合键占用按住锁定，必须确认释放再接受有效键。
- ACK失败丢弃尚未完成的去抖计数，但保留已按住锁定；不会以通信失败冒充释放。
- 调速目标将原15..100%范围线性分配到15..40/60/80/100%。1874周期计数下端点为281和749/1124/1499/1874。情景1/2/3目标为374/1874/1874，忽略模拟扳机深度；启动许可仍由原扳机去抖/方向/故障状态机控制。
- `user_para_init()` 初始化新模式；`user_gears_handle()` 调用新目标函数，未改底层电机斜坡/保护；`TOOL_POWER_DOWN` 在EN拉低之前调用同一保存门控。
- `tool_mode_save_handle()` 仅在松扳机、MOTOR_STOP、motor_en=0、gToolEn=0时调用保存。成功才清pending；运行中只修改RAM并推迟保存。旧 `save_user_data()` 接口仍走同一门控。

### 持久化协议

页地址0x08007800和0x08007C00，每页51槽，每槽20字节，尾部4字节保留。新记录使用前8半字：

| 半字 | 内容 |
|---|---|
| 0 | 0xA65A，最后写入的提交标志 |
| 1 | 版本1 |
| 2 | 模式0/1 |
| 3 | 调速挡位1..4 |
| 4 | 情景挡位1..3 |
| 5/6 | 32位序号，低/高半字 |
| 7 | CRC16-CCITT，初值FFFF，覆盖半字1..6，每半字低字节在先 |

启动扫描两页全部槽，跳过无效/残缺记录，根据带自然回绕处理的序号恢复最新有效配置。找空槽要求整个20字节均为FFFF，残缺槽不重复编程。

正常在最新有效页的空槽追加。页满时只擦另一个页；HAL返回成功后整页读回FFFF，再逐半字写数据并读回验证，最后写magic并验证整个记录。最新有效页在新记录写入/读回成功之前始终保留，擦除或任一写入失败不清pending。

当无有效新记录时兼容读取旧页31首10槽的 `[0x55AA, gear, auto_stop]` 三半字记录，旧0/1挡转换为调速1/2档，情景默认1档。旧自动停机标志兼容读取；新产品的持久化内容仅为模式和两种模式挡位。旧格式缺少CRC，因此只能检查标志和字段范围。空Flash或全部损坏回退调速1档，不启动时重写默认。

移除了仅在旧Flash模块内部使用、仓库无外部调用的任意数组读写接口，保留 `read_half_data`、`save_user_data`、`read_user_data`，新增 `uint8_t save_user_data_checked(void)`。

## 集成条件与实际边界

- 主代理须将工程ROM限制30KB，加入tool_mode.c/头和TM1650 include路径；主循环在目标计算前调用key_handle，motor_en发布后调用保存门控。主循环以key_handle的返回值避免同一1ms同时进行键盘读与显示总线写。
- 未执行完整Keil工程clean rebuild或目标板测试，主代理负责最终构建、全套回归和交付。
- 即刻断电发生在运行中时，本次未到停机保存窗口的RAM变化不能承诺已持久化；已提交设置可以在擦页/半写断电后恢复。持续Flash物理故障会保留pending并尝试后续停机保存；失败时EN关断仍按原休眠流程执行，恢复的是前一有效设置。
- Flash物理操作为前台阻塞，HAL声明页擦约6ms、半字写约155us；停止状态下进行，不屏蔽/修改保护和看门狗。主循环可能丢失这段时间中的1ms前台任务；需要目标板检查按键响应、看门狗、断电保存和EMI。
- 需目标板验证15%初始与20%情景低档的实际启动可靠性、换向联锁、负载/堵转/电流/温度/欠压安全行为。软件ARM模拟不能代替这些电气验证。
