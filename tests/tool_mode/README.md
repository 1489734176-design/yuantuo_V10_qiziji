# 模式和掉电记忆 ARM 回归

在仓库根目录执行：

```powershell
& 'D:\Program Files\Python314\python.exe' 'tests/tool_mode/run_tests.py'
```

测试使用安装的 Arm Compiler 6 编译实际 `tool_mode.c`、`flash_data_save.c`，抽取实际用户初始化/目标处理和 `pwm_set` 函数，并在 Unicorn Cortex-M0 中运行。TM1650键盘应答和Flash物理写擦由模拟硬件替代，Flash模拟保持仅允许1→0编程的约束。构建输出位于 `.planning/2026-11-05-reverse-scene-memory/control-tests/`。

覆盖双模式切换和独立档位、按下/释放三样本去抖、按住不重复、ACK失败保持锁定、未知/组合键、各档扳机端点与中间值、真实PWM斜坡、安全保存门控、半写/CRC损坏回退、双页51槽换页和擦写失败、版本/字段范围拒绝、序号回绕与旧三半字记录迁移。

`--baseline` 对任务开始时的 `original` 快照运行40%默认上限断言，预期失败，证明旧固件缺少新行为。此回归不能代替目标板验证。

2026-11-05后续回归增加扳机按住屏蔽K2/K3、松扳机后按键释放重按、失败读键不能解锁以及未完成去抖被短扣动打断。挡位期望同步当前38/58/78/100%设置，斜坡等待次数同步既有6次中断/步进1参数；生产调速及斜坡配置未改动。

2026-11-05反转回归增加K3调速/情景4切换、双方向mode/speed/scene记忆、实际满值后849/850ms边界、前台丢帧计时、保护降低实际PWM不延长阶段、失去运行许可复位、原PWM升降斜坡，以及双方向v2日志的半写切点、CRC损坏和v1迁移。双方向均处于调速时，真正换向将离开方向的当前调速档位交接给目标方向；涉及情景模式时仍恢复各方向独立记忆。首次上电方向同步只恢复对应方向记忆，不触发调速交接。当前主模式回归为26用例。

参数化脚本编译实际模式/LED模块，分别验证默认及覆盖配置。调速1～4档累计亮LED8、8+7、8+7+6、8+7+6+5，默认显存期望为0x40/0x60/0x70/0x78；覆盖灯号参数后期望为0x08/0x48/0x58/0x78。覆盖头仅参与测试；正转情景默认18/100/100%，单灯序8/7/6，反转情景默认单亮LED5、100%保持850ms后降15%。覆盖配置还改变反转灯号、升降占空比和保持时间，以验证配置实际生效。

七灯回归使用实际方向门控，验证运行期间保持原方向及灯显、停机松扳机后双调速交接，以及双向交接后的累计灯显。TM1650集成回归通过边沿级硬件模型运行真实读键、去抖、模式和显示总线，共5用例；其中双调速交接与涉及情景的三种换向组合使用不同的档位记忆验证可见结果。这些模拟检查均不能代替目标板验证。
