# 新版方灯 7LED 板适配（2026-11-03）

依据资料目录中的 `NX32F002-28T-方灯-7LED.pdf`，灯驱动和报警编号参考用户指定的 shenghong/20260909 工程。

| 逻辑灯 | 原理图灯 | 阳极 / 阴极 | 显示规则 |

| LED1 | LED4 | PA14 / PA13 | 电量第1灯、报警 |

| LED3 | LED6 | PA14 / PA10 | 电量第3灯、报警 |

| LED6 | LED3 | PB8 / PA10 | 参考挡位显示 |

`Wrench_EN=0` 保持当前电钻配置，因此参考程序的挡位灯逻辑仍不启用。KEY 的采样和去抖接口已经接入，未新增挡位功能。

首次电量显示直接按当前电压初始化等级，即使扳机上电后立即运行，也会显示相应电量。后续保留参考程序的运行期间保持等级、松手停机后更新和0.2V滞回，避免负载瞬时压降引起跳灯。最低电量仍闪烁第1灯，故障闪灯优先于电量显示。

## 扫描及方向联锁

TIM1 每个 PWM 周期调用一次扫描。按参考程序的6灯12槽顺序扩展为7灯13槽：第1～7槽扫描各灯，第8～11槽将两路行和四路COM全部设为模拟输入高阻，第12槽拉高并输出COM、将 PB8/PA14 设为上拉输入，第13槽读取方向和按键，随后将两行恢复为推挽低电平。16kHz PWM 下，全高阻窗口250us，输入稳定时间62.5us，完整扫描周期812.5us。

每次切灯先关闭两路行输出，再清除CNF配置、拉高全部公共阴极，最后驱动选中行列。PA13公共端参与每轮高阻释放，不再持续推挽驱动。输入任务只读窗口采样缓存。新图没有灯脚与 ADC 共用，因此保留参考的四槽高阻时序，但不启用`led_reuse_adc_flag` ADC门控。休眠时点灯槽保持高阻，仅保留输入准备/采样。

`Bsp_Gpio_Init()`不再提前调用共享DIR/KEY初始化；校准后的`led_init()`才按参考切换PA13/PA14复用并将矩阵初始化为浮空输入。保留原有100ms校准期间的SWD启动连接窗口，扫描未启动时直接返回，不改写GPIO。

## 烧录口及重复烧录

芯片PA13/SWDIO和PA14/SWCLK的默认复用为AF0；参考程序在灯初始化中同样将其改为AF1，之后没有动态恢复AF0。四槽模拟输入只释放输出，不等于恢复SWD。此次修复纠正了提前接管PA14和永久驱动PA13两个差异；程序已运行并复用引脚后，不能据此承诺烧录器可随时连接。

用户工具为`LCD_ALL_PRGMR_V41`。已烧入旧固件的板需让MCU真正复位，再由烧录器在应用重新接管引脚前连接：若NRST有效且工具支持，可用硬件复位连接；否则需要目标板真正断电重上电，并由烧录器及时连接。仅关闭软件或拔烧录器USB不一定让目标MCU断电。未修改读保护、NRST选项或烧录器配置。

新图的四针烧录接口仅有电源、地、SWDIO和SWCLK，未引出NRST，因此当前接线尤其需要核对目标板断电重上电的连接方式。

本地烧录器版本说明列明MM32SPIN023x支持需烧录器固件13.25及以上，但未提供其目标上电/复位连接操作说明。目标实际NRST选项、烧录器固件版本和连续烧录仍需实板核对。本次未操作烧录、擦除或解除保护。

扳机同时是板子的上电来源。上电先滤波扳机，再去抖方向；首次方向确认只是同步开关位置，确认采样有效、方向稳定且电机停止后，允许当前这次扣动启动，不要求先松手。`direction_initialized` 将这次初始同步与后续换向分开，首次同步也不会绕过故障启动许可。

运行中换向先撤销运行许可，电机停稳并松开扳机后才更新方向；所有停止到运行的路径都检查方向有效和重扣锁定，包括原有制动续启路径。首次确认完成之后发生的采样失效同样保留松手联锁，不会再次走初始同步分支。

## 报警次数

三个电量灯同步报警，沿用参考的灭500ms / 亮约200ms、一组结束间隔1500ms、每次调度10组的节奏。扳机松开后回到正常电量显示。

| 次数 | 故障 |
|---|---|
| 1 | 硬件过流 `gIBusAcmpOCP` |
| 2 | 电池温度（编号保留，本版检测不启用） |
| 3 | MOS 过温或热过载 |
| 4 | 堵转 |
| 5 | 软件峰值过流、一级/二级/三级平均过流 |
| 6 | 待机/运行欠压 |
| 7 | 飞钻 |
| 8 | 过压 |
| 9 | MOS 上/下桥臂异常 |
| 10 | 缺相 |
| 11 | 失步 |
| 12 | 电池通信（编号保留，新板无此电路） |
| 13 | 四级平均过流 `gIBusAvgOCP4` |
| 14 | 其他未分类故障 |

1～12 的编号和判定优先级与参考程序一致；参考的兜底13次顺延为14次，故障码由矩阵电量灯显示。

## 关灯及休眠

按用户要求取消独立照明的正常10s、故障长按30s和故障松手立即熄灭逻辑。参考程序使用`SLEEP_TIME=5000`：正常或故障后松开扳机，约5s后进入`TOOL_POWER_DOWN`，电量/挡位矩阵灯全部熄灭。新板PA12独立照明同样随休眠关闭，取消照明状态对整板休眠的附加限制。

扳机再次扣动并进入运行会清零休眠计数，下一次松手重新计时；故障时持续按住扳机，休眠计数保持清零，矩阵继续报警、照明保持亮，不再有30s关灯。松手后矩阵恢复电量显示并开始5s休眠计时。沿用参考的`++sleep_cnt > SLEEP_TIME`边界，即停止态第5001个1ms任务进入休眠，随后任务拉低PA11电源保持。

## 配置变更

- `LED_SCAN_EN`: 0 → 1。
- `BAT_COM_EN`: 1 → 0。PA11/12/14 已分配给新板 EN/照明/KEY，不得直接重新启用旧板通信配置。
- `EN_BAT_TEMP_DETECT`: 1 → 0，按用户要求将 DS/TBAT 作为预留接口。
- `MOS_NTC_10K_3435K`: 1 → 0；`MOS_NTC_100K_3950K`: 0 → 1。
- `MOS_TEMP_UP_RES`: 10K → 4.7K；95℃保护、85℃恢复的温度目标保持不变，使用工程已有100K/B3950阻值表重新计算 ADC 阈值。
